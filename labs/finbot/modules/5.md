# Module 5: Clean it

A vendor asks [FinBot](glossary.md#finbot) to show the details it holds for their account. FinBot looks the vendor up, and the record it gets back includes the bank account number. In this module you keep that number away from the model while FinBot still answers the vendor.

## What you'll see

With [ACS](glossary.md#acs) off, the vendor record reaches the model whole. You read the bank account number yourself in the [model input log](glossary.md#model-input-log).

With ACS on, the [Guardian](glossary.md#guardian) answers the vendor lookup's [tool result](glossary.md#tool-result) with a modify [decision](glossary.md#decision). Modify lets the step go on, with changes. The [gateway](glossary.md#gateway) swaps the number for `[REDACTED]` before the model reads it. FinBot still finishes its reply, with the number masked.

With ACS off, run the scenario. Then print the last request the gateway sent to the model.

```sh

```

The output is long. Use your terminal's search to find the last `function_call_output` item, the place where a tool's output goes back to the model.

That item holds the vendor record exactly as FinBot's `get_vendor_details` tool returned it. Its `bank_account_number` field shows the full number, twelve digits in plain text. The model read every digit of it.

## Run it with ACS on

Open `policy/redact_bank.rego`. The starter's rule body ends in `false`, so it never matches, and the number goes through.

Your job is a rule that adds a redaction path for every `bank_account_number` key in the output. A redaction path names one field for the gateway to mask.

Each path is a JSON Pointer, the slash-separated route to one field that RFC 6901 defines. For the flat vendor record, that's `/outputs/0/value/bank_account_number`.

`walk()` is a [Rego](glossary.md#rego) built-in that visits every value in the output, with its path. So one rule covers nested records and lists too.

Try writing the rule yourself first. If you get stuck, replace the starter's whole rule, from `redaction_paths contains` to its closing brace, with the lines below. Keep the `package finbot` line above it.

```rego
sensitive_key := "bank_account_number"

# A key can hold ~ or /. A JSON Pointer writes ~ as ~0 and / as ~1, and ~ must go first.
pointer_token(token) := replace(replace(token, "~", "~0"), "/", "~1") if is_string(token)

pointer_token(token) := format_int(token, 10) if is_number(token)

redaction_paths contains pointer if {
	input.method == "steps/toolCallResult"
	walk(input.payload.outputs, [path, _])
	count(path) > 0
	path[count(path) - 1] == sensitive_key

	# A field inside another redacted field is already gone, and a second path would overlap it.
	not sensitive_key in array.slice(path, 0, count(path) - 1)
	pointer := concat("/", array.concat(["", "outputs"], [pointer_token(t) | some t in path]))
}
```

The two `pointer_token` lines turn each step of the path into pointer text, a key or a list index.

The Guardian checks the paths before it answers (issue #469). It denies the whole result in three cases:

- A path doesn't point at a field that exists.
- Two paths overlap.
- One occurrence of the key is left out.

## What changed

The vendor lookup ran the same way both times. The difference is what the model got to read.

With ACS off, the gateway passed the tool result straight to the model. With ACS on, the gateway sent it to the Guardian as `steps/toolCallResult` first.

The Guardian ran your [policy](glossary.md#policy) and answered modify with the reason code `sensitive_field_redacted`. The gateway applied the redaction, then forwarded the edited result.

Only the exact key `bank_account_number` is redacted. FinBot's payments [agent](glossary.md#agent) reads `vendor_bank_account_number` from an invoice and passes it to `create_transfer`. Redacting that key too would break payments, so the rule leaves it alone.

## What ACS gave you

You changed what the model reads without touching FinBot's code. The redaction happens at the gateway, between the tool and the model.

FinBot never talks to the Guardian, and the gateway applies the redaction before the model reads the result. So FinBot can't bypass it. <!-- claim:C-17 -->

When a step is denied outright, the model reads the [neutral deny line](glossary.md#neutral-deny-line) in its place. A redaction removes less. The rest of the record still reaches the model, so FinBot can finish its task. <!-- claim:C-17 -->

The [audit log](glossary.md#audit-log) records the modify for each enforce run. The model input log shows you exactly what the model read, in every mode.

## What this doesn't show

A number inside a plain string output isn't redacted. A redaction path points at a JSON key. A tool that returns `"bank_account_number: 111"` as one string has nothing to point at, so the number goes through. The lab leaves that case open.

The rule matches the key name only. A bank number stored under any other key, or typed into a chat by the vendor, reaches the model.

The policy input, the verdict shape and the redaction paths are a lab convention until issue #531 settles how ACS binds to OPA. <!-- claim:C-13 -->

## Check your work

```sh
./lab.sh check 5
```

The check reads the newest enforce run of `s5`. It passes when that run holds the modify on the `get_vendor_details` result. No line the gateway logged to the model input log during that run may hold the bank account number.

FinBot's reply must also be there, and it can't be the neutral deny line. The check also prints one line about your newest off run, so you see the before and after together. Neither line ever prints the number.

A pass reads like this, with your own run id:

```text
DONE: enforce run 20261209T110000Z-s5 redacted the get_vendor_details result (sensitive_field_redacted), no model input line held the bank account number, and FinBot still answered the vendor
```

Before any enforce run, a NOT YET line starts "there's no enforce run of s5 yet" and names the commands to run.

Checks read `state/`, so anything that can write `state/` can steer a check. A check believes the files it finds there, so a file planted there could fool it. That is this lab's [trust boundary](glossary.md#trust-boundary), and module 7 comes back to it.
