The runtime control plane for AI agents.

OWASP GenAI Security Project Agent Control Standard (ACS) is the open standard that defines how agent platforms expose middleware hooks and how open-source tooling enforces safety policy through those hooks. Declarative controls. Portable across frameworks. Enforced at runtime.

Agents are shipping fast. Controls are not

AI agents act across organizational boundaries. The industry standardized how agents communicate through MCP and A2A, and documented the risks through the OWASP Agentic Top 10. Runtime control never got the same treatment.

  • System prompts are not controls.
  • Model improvements do not cover edge cases or adversarial inputs.
  • Proprietary guardrails create vendor lock-in.

Three layers, one standard

Instrument

ACS defines hooks at the agent's decision points. The agent asks a separate Guardian before it acts, and the Guardian answers allow, deny, modify, ask, or defer.

Trace

ACS defines how each step maps to an OpenTelemetry span and an OCSF event. In release 0.1.5, the gateway and the TypeScript AGT Guardian export OpenTelemetry spans. No component emits OCSF yet, and OCSF output is planned.

Inspect

Enterprises cannot secure what they cannot inventory. AgBOM captures tools, models, and dependencies as the agent acquires them, which a static SBOM cannot do.

How it works

1. The agent asks

Before a step runs, the agent sends it to the Guardian as a signed JSON-RPC request over HTTP. Adapters do this for Claude Code, Cursor, and NVIDIA NAT through each host's own hook configuration, and a gateway does it for any OpenAI Responses client without code changes.

2. The Guardian decides

A separate Guardian evaluates declarative policy and returns one of five dispositions. The two AGT-based Guardians use Rego, a policy language. The example Guardian uses a short built-in rule table by default, or, if you opt in, an OPA (Open Policy Agent) server running Rego. When no usable answer arrives, the adapters and the gateway block the step by default.

3. The record holds

The Guardian keeps a hash-chained audit record of every decision. The gateway also writes a transcript of every envelope, each signed message it exchanged with the Guardian, which acs-verify, the project's verification tool, checks offline.

Release ships three Guardians, three adapters, and the gateway. Run a Guardian shows where to start.

Why now

The EU AI Act requires high-risk AI systems to be designed for effective human oversight, including the ability for a person to intervene in or interrupt the system (Regulation (EU) 2024/1689, Article 14). The NIST AI Risk Management Framework, which is voluntary guidance rather than regulation, describes continuous monitoring and the ability to deactivate systems operating outside intended limits (NIST AI 100-1, MANAGE 2.4).

Both describe controls that exist at runtime. Neither is satisfied by a system prompt.

Built with the community

ACS maps onto standards your teams already run. It adds a control layer rather than replacing any of them.

  • OWASP ASI The agentic risk taxonomy ACS controls are written against.
  • AIVSS A complementary OWASP system for scoring agentic AI risk.
  • OpenTelemetry One way ACS records trace data.
  • OCSF The event schema ACS maps each step onto for the SIEM.
  • CycloneDX One serialization for the Agent Bill of Materials.
  • SPDX A second AgBOM serialization, for teams already standardized on it.
  • MCP A tool protocol ACS hooks wrap without modifying.
  • A2A An agent-to-agent protocol. Specification v0.1.0 reserves its namespace, and wrapping is planned for v0.2.0.

Contribute

ACS is working toward one committed outcome right now, and contributions are accepted against that outcome rather than against an open-ended list of ideas.

Read the full priority scope before you file anything. Work that a maintainer has already accepted carries the help wanted label. Ask a lead to assign it to you before you start.

  • Join OWASP Slack and the #team-genai-asi-acs-general channel.
  • Propose new work through the issue forms. Only an accepted issue enters the backlog.
  • Read the decision log for what the project has decided and why, including choices the specification text does not reflect yet.
  • General questions about the project: rock.lambros@owasp.org

Reporting a problem

Report a security vulnerability through GitHub private vulnerability reporting, which is the channel our security policy covers. Report a Code of Conduct concern through the OWASP Code of Conduct process, which handles reports independently of this project's maintainers.
