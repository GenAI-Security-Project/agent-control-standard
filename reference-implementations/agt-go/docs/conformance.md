# Conformance

This table compares the Go Guardian with ACS-Core as defined on `integration` in
[docs/spec/conformance.md](../../../docs/spec/conformance.md).

ACS v0.1.0 has no external certification mechanism. The Go Guardian self-declares
`acs-core`; each claimed row names the tests that cover it. `make docs-check`
verifies that those tests and the document's local links exist. It cannot prove
that a test's assertions establish a claim; code review and `make check` provide
that assurance.

## Dispositions

The Guardian supports all five, each covered with a test engine. The default
AGT policy bridge uses the checked-in policy deployment and emits fewer;
running it does not exercise all five.

| Disposition | Guardian | Checked-in AGT policies |
| --- | --- | --- |
| allow | yes | yes: `allow`, and `warn` with a policy reference |
| deny | yes | yes: `deny`, and every `runtime_error:*` |
| modify | yes | yes: `transform`, the shipped redaction rules |
| ask | yes | only with an approver configured; the checked-in configuration never escalates, and without an approver an escalate is DENY `approver_unavailable` |
| defer | yes | no: mapping.yaml maps no AGT verdict to defer |

## Behavior that ACS v0.1.0 leaves undefined

ACS v0.1.0 requires each result listed below, but it does not fully define the
wire field or algorithm needed to produce that result. The second column states
the exact behavior implemented here. Two implementations must make the same
choice to interoperate on that point.

| What ACS v0.1.0 leaves undefined | Behavior implemented here |
| --- | --- |
| ACS-Core requires every answer to be signed, but `response-envelope.json` defines no signature field for an error. | An error answering an authenticated request stores the signature in `error.signature`. This matches the `signature` field of an `AcsResult`, and the error schema permits the additional field. The Python adapters in PR #22 use the same location. An error answering an unauthenticated request is unsigned. |
| §10 requires every response to be signed, but `handshake.json` defines no signature field for `ServerHello`. | `ServerHello` stores the signature in `result.signature`. This matches the `signature` field used by an `AcsResult`, and the `ServerHello` schema permits the additional field. |
| turnStart requires `turn_id` on every per-step ContextEntry; `context-entry.json` names no member for it. | The entry carries `turn_id`, the envelope field's name, inside its hash. |
| §9.1 requires an `intent_extension` entry to record the approver, the capabilities and the extension's provenance; `context-entry.json` names no members for them. | The entry carries `approver` and `intent_extension`, the names `ask-details.json` uses, inside its hash. |
| ACS v0.1.0 defines no wire method for sending an approver's answer to the Guardian (#175). | The `PolicyEngine` receives the answer by its own means. On a later policy evaluation, the engine authenticates the approver and returns the grant. The Guardian then checks that the grant answers an ASK from the same session. |
| `post-compact.json` asks for `post_compact_chain_hash`, the chain head after the entry that carries it; that entry's `request_hash` commits to the value, so no sender can compute it. | The value is not checked; the answer's `chain_hash` publishes the head. `pre_compact_chain_hash` is checked. |
| §6.3's `parameter_overrides` name tool arguments; nothing says what they name in a wrapped MCP message. | For a wrapped `tools/call`, they name members of `params.arguments`. |
| ACS v0.1.0 defines no way to notify the Observed Agent that a DEFER has been resolved. | The Go Guardian adds no wire method. The Observed Agent may learn of it by other means, outside ACS. The Observed Agent can then submit the step again, and a policy engine that remembers the resolved case can return the final decision. |
