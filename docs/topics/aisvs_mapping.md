# Map ACS to OWASP AISVS 1.01

Security teams that verify agentic systems against [OWASP AISVS 1.01](https://github.com/OWASP/AISVS/tree/main/1.01/en) need to know which of its requirements an Agent Control Standard (ACS) deployment meets on the wire, and which need something more. This page maps the ACS conformance profiles against every requirement in the five AISVS 1.01 sections closest to ACS: C5.2, C6.2, C9, C10 and C12.

The mapping is mechanism to requirement. It adds no normative text and changes no schema or hook. A verdict describes what the specification requires of a conformant deployment, not what any one implementation does.

AISVS 1.02 development text is not used. The ACS schemas under `/schema/v0.1.0/` have changed in place between releases, so every ACS citation below links to the 0.1.5 release commit, not to the current text.

## Read the verdicts

| Verdict | Meaning |
|---|---|
| Covered | An ACS-Core MUST, or a MUST in the named profile, makes a conformant deployment meet the requirement at the wire and runtime-contract layer. |
| Partial | ACS meets part of the requirement, or meets it only with an optional profile, a negotiated setting, or a SHOULD or MAY. The row says which part, and what else is needed. |
| Gap | The requirement falls within what an agent-control wire could address, and ACS 0.1.5 does not address it. The row links an open ACS issue where one exists. |
| Outside what ACS specifies | The requirement concerns something ACS leaves to deployments by design, such as MCP server internals, training data or infrastructure access management. These are listed under each table with a one-line reason. |

Profiles are self-declared in the handshake, and nobody verifies a conformance claim in v0.1.0 ([conformance L50](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/spec/conformance.md#L50)). A verdict that names a profile assumes the deployment declares and implements it.

Decisions the leads have made but the 0.1.5 text does not yet carry do not count toward a verdict. Three such decisions appear in the rows: [D-036](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/decisions/index.md#d-036-default-the-failure-posture-to-deny) makes deny the default failure posture, [D-038](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/decisions/index.md#d-038-carry-model-identity-as-fields-on-existing-hooks) carries model identity on existing hooks (accepted in shape, details open), and [D-043](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/decisions/index.md#d-043-treat-ask-as-a-soft-deny) treats an unanswered ASK as a deny. [D-044](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/decisions/index.md#d-044-manage-agbom-as-an-acs-sub-stream-and-map-it-to-cyclonedx-first) is different: a scope decision that needs no spec change. It keeps the Agent Bill of Materials (AgBOM) inside ACS, separate from the AI BOM effort that covers models.

No requirement is fully covered by ACS 0.1.5 alone. Three causes account for most partial verdicts:

- **Decision failure fails open by default.** In 0.1.5 the Observed Agent applies `on_decision_failure`, which defaults to `proceed` ([specification L223](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/spec/instrument/specification.md#L223)). A requirement that something is blocked is met only when the deployment negotiates `deny`. The leads decided to make deny the default (D-036), but the 0.1.5 text has not changed.
- **The check itself is Guardian policy.** ACS gives the decision point and requires the agent to honor the decision. What the Guardian checks is its own policy, and a permissive Guardian is still conformant ([conformance L48](https://github.com/GenAI-Security-Project/agent-control-standard/blob/e2519b99ef0fc9bca7ee6d37e0ac0aa0234f1780/docs/spec/conformance.md#L48)).
- **The mechanism is optional.** MODIFY is SHOULD-support, several hooks are SHOULD-implement, and some controls exist only in the Trace, Provenance, Inspect, Inspect-Dynamic or Crypto profiles.
